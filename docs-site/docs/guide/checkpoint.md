# 检查点与撤销

在 AI 执行文件修改操作前，Aharou 会自动保存改动前的文件快照并创建检查点。如果生成结果未达预期或引入了意外问题，可随时一键回退到指定节点。该机制完全自动运行，无需手动干预。

## 回滚方式

在聊天记录里找到你想退回的那条**你自己发的消息**——撤销图标在气泡**下方**的元信息行里，排在时间戳、复制按钮之后（就是那个 ↺ 回退箭头），点开就是该检查点的操作菜单。

菜单里有三个选择：

| 操作 | 代码 | 对话 |
| --- | --- | --- |
| 恢复代码与对话 | 回到这条消息之前的状态 | 删掉这条之后的消息，原来的提问会填回输入框 |
| 仅恢复对话 | 保持现状不变 | 删掉这条之后的消息 |
| 仅恢复代码 | 回到这条消息之前的状态 | 保持完整不变 |

选择涉及代码恢复的选项后，确认框会显示同一份预览中的目标时间、预计还原数和预计跳过数。大范围回退会标明只预览了部分文件；执行时仍检查全部文件。关闭菜单不改变确认目标，切换会话会关闭待确认操作。没有可用代码检查点（例如分叉会话里的旧消息）时，仍可明确选择「仅恢复对话」；不会因代码目标失效而自动截断对话。

常用的是第一个：相当于"这一轮重来"，代码和对话一起回到起点，你可以改一下提问再发一次。

如果你只是想让 AI 忘掉走偏的几轮讨论、但保留它已经写好的代码，用「仅恢复对话」。反过来，代码想扔掉、讨论过程想留着复盘，用「仅恢复代码」。

恢复对话会删除所选消息及后续消息，撤销现有压缩摘要，并恢复回退点之前保留的原始对话，避免摘要带入后续事实。「仅恢复代码」不改变对话。恢复后历史过长时，下一次发送前会重新压缩；已经发生的调用用量不会清零。旧版已经截断或缺失的内容无法凭回退补回。

## 冲突检测与撤销恢复

检查点固定到创建时的执行目录与环境，查看、回退和撤销都不会跟随当前选中的工作区。独立工作树中的检查点只操作该工作树；无法确认历史检查点的执行归属或环境已失效时会跳过并提示，不猜测当前目录。

文件工具在同一资源锁内采集写前快照、写入和写后摘要，避免将其它会话的后续改动登记成自己的写入。回退前会先比对每个文件的现状与「AI 写入后的样子」：

- 文件仍是 AI 写下的内容 → 照常回退；
- 文件被**检查点之外的操作**（你自己手动改的、终端命令改的）动过 → **跳过它**并弹窗列出，避免把这些改动冲掉。

同一文件跨多轮修改时，只计为一个文件。程序会在写入或删除前检查它的整条快照链；其中任何一步有冲突，就保留该文件当前状态，继续处理其他文件。AI 新建的文件也遵循这一规则。

回退菜单里还有一项「**撤销上次恢复**」：把最近一次代码恢复回滚回恢复前的状态，用于刚点错回退的场合。没有备份节点时不能撤销。撤销也会检查恢复后的外部改动；有未处理文件时，结果会分别列出跳过或处理失败的路径，时间线保留对应条目。文件删除失败不会算作已恢复。如果选择「恢复代码与对话」时发生文件处理失败，对话历史会保留；想只退对话时可单独选择「仅恢复对话」。

它下面跟着「**恢复时间线**」：每次恢复、每次撤销各自留下一个时间节点（几点、涉及几个文件），最多留 20 个。点其中一个节点，文件就回到那个时候的样子；撤销本身也会留一个节点，所以来回跳都不会丢东西。

## 适用边界与限制

检查点只记录 AI **通过文件工具**做的修改。如果文件是被终端里的命令改掉或删掉的（`rm`、`mv`、`sed` 这类，无论是你自己敲的还是 AI 执行的），检查点无法精确还原。

这种情况下建议通过 Git 恢复：只要文件曾被 Git 跟踪过（提交过一次就算），去 Git 页的状态标签页长按那个文件，选「恢复文件」或「回退改动」就能取回来，跟它是怎么被删的无关。反过来说，从没提交过的新文件不在这层保护里。

重要的项目建议同时用 Git 管起来，检查点适合处理单轮改动的回退，Git 才是完整的版本安全网。
